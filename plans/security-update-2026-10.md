### Conclusion and focused next step

Keep the native unstable server/ML selection: the wiring is correct and the reviewed application fixes are present. **Do not describe 3.3.5 as complete public-service security coverage or rollout-ready on version alone.** Two additional native-packaging findings need resolution/explicit acceptance before public rollout:

1. **Node security release is not inherited from the Docker image.** Unstable's Immich derivation takes `nodejs`, aliased to `nodejs_24`, currently **24.21.0**. Its listed patches do not backport October's Node JS-level fixes; upstream's fixed 24.x release is **24.22.1**. The shared build definition uses external Brotli 1.2.0 without the CVE-2026-111497 patch for Node major 24 (the conditional backport applies only to the other majors). Thus upstream's 3.3.5 Docker security announcement does not establish the equivalent fixes in this native package. A library/runtime gap is established, not an exploit against this service. Prefer an upstream/native nixpkgs refresh that provides the fixed Node 24 runtime and Brotli; do not silently switch Node majors or override Immich locally. [Node advisory](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases), [Node selection](https://github.com/NixOS/nixpkgs/blob/3ec636362e1816bc2f0888fa0fa2c69f1bc9e504/pkgs/top-level/all-packages.nix#L2269), [24.x package](https://github.com/NixOS/nixpkgs/blob/3ec636362e1816bc2f0888fa0fa2c69f1bc9e504/pkgs/development/web/nodejs/v24.nix), [shared libraries](https://github.com/NixOS/nixpkgs/blob/3ec636362e1816bc2f0888fa0fa2c69f1bc9e504/pkgs/development/web/nodejs/nodejs.nix#L136-L161).
2. **SVG/ImageMagick fix is distribution-specific.** Newly checked [GHSA-q89f-h332-8q2h](https://github.com/immich-app/immich/security/advisories/GHSA-q89f-h332-8q2h) reports authenticated SVG-to-ImageMagick RCE in Docker 3.2.2, fixed in Docker 3.2.4. The 3.2.2→3.2.4 source comparison changes the server base images, not an application-level SVG guard. Native Immich builds Sharp against system libvips; pinned libvips **8.18.7** includes ImageMagick, and neither the package wrapper nor our module sets `VIPS_BLOCK_UNTRUSTED`. Native **`services.immich.environment.VIPS_BLOCK_UNTRUSTED = "1"`** is a candidate mitigation requiring no glue, unit or override: libvips reads this environment variable on initialization and marks its Magick7 loader untrusted. Recommend reviewing/testing this setting next, including representative RAW/HEIC/SVG imports and any formats dependent on untrusted fallback loaders. Do not equate the Docker root/write-to-ffmpeg PoC with demonstrated native RCE: Nix uses an `immich` service account and immutable store executables. Conversely, those differences do not prove the fallback safe. [Native libvips](https://github.com/NixOS/nixpkgs/blob/3ec636362e1816bc2f0888fa0fa2c69f1bc9e504/pkgs/by-name/vi/vips/package.nix), [environment switch](https://github.com/libvips/libvips/blob/v8.18.7/libvips/iofuncs/init.c#L666-L669), [untrusted loader](https://github.com/libvips/libvips/blob/v8.18.7/libvips/foreign/magick7load.c#L357-L360).

These are review findings/recommendations only; no mitigation or input refresh was implemented here. Keep Pillow **12.3.0** as a separate unresolved ML dependency, not a reason to discard the application upgrade or claim service-level RCE. Fixing only stable's Python package set would not cover unstable's ML worker.
